## 1. 전체 네비게이션 구조

### 페이지 흐름도

```text
사용자 앱 모드 선택
        │
        └── 관리자 모드 ──→ 관리자 Streamlit 앱
                                  │
                                  ▼
                           관리자 로그인
                                  │
                                  ▼
                            사용자 관리
                              ├── 사용자 상세보기
                              │     ├── 프로필
                              │     ├── 퀘스트 진행
                              │     └── 접속기록
                              ├── 로드맵 관리
                              └── 공지사항 관리
                                    └── 공지사항 상세보기

준비 중 화면
  └── 채용공고 관리 ──→ 채용공고 등록·편집
      (현재 네비게이션 미등록)
```

### 사이드바 네비게이션

로그인 전:

```text
┌────────────────────────┐
│ 취업관리 MAP           │
│                        │
│ 로그인 하여 관리자     │
│ 기능을 이용하세요.     │
└────────────────────────┘
```

로그인 후:

```text
┌────────────────────────┐
│ 취업관리 MAP           │
│────────────────────────│
│ 🗃️ 사용자 관리         │ → 사용자 목록
│ 🧭 로드맵 관리         │ → 사용자별 로드맵 조회
│ 🪧 공지사항            │ → 공지사항 목록
│ [로그아웃]             │ → 세션 초기화 후 로그인
│────────────────────────│
└────────────────────────┘
```

### 페이지 등록 정보

| 페이지명 | 파일 경로 | 아이콘 | 네비게이션 방식 | 현재 접근 상태 |
|---|---|---:|---|---|
| 관리자 로그인 | `frontend_admin/app_pages/start.py` | 🏠 | 기본·hidden | 접근 가능 |
| 사용자 관리 | `frontend_admin/app_pages/user_management.py` | 🗃️ | sidebar | 로그인 후 노출 |

| 공지사항 관리 | `frontend_admin/app_pages/notice.py` | 🪧 | sidebar | 로그인 후 노출 |
| 공지사항 상세보기 | `frontend_admin/app_pages/notice_detail.py` | 🪧 | hidden, 목록의 수정 버튼 | 접근 가능 |

## 01. 관리자 로그인 (Admin Login)

**파일:** `frontend_admin/app_pages/start.py`  
**스크린샷:** 미등록 (소스 기반 기술)  
**테마:** Streamlit 기본 Light 테마

### 화면 구성

```text
┌────────────────────────────────────────────────────────────┐
│ 취업관리 MAP                                               │
│                                                            │
│ 관리자 로그인                                              │
│                                                            │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ 아이디                                                 │ │
│ │ [관리자 아이디                                      ]  │ │
│ │                                                        │ │
│ │ 패스워드                                               │ │
│ │ [••••••••••                                         ]  │ │
│ │                                                        │ │
│ │ [                    로그인                          ] │ │
│ └────────────────────────────────────────────────────────┘ │
│                                                            │
│ 로그인 하여 관리자 기능을 이용하세요.                      │
└────────────────────────────────────────────────────────────┘
```

### 주요 UI 요소

| 요소 | 유형 | 설명 |
|---|---|---|
| 관리자 로그인 | Subheader | 로그인 화면 제목 |
| 아이디 | Text Input | 관리자 로그인 아이디 입력 |
| 패스워드 | Password Input | 관리자 비밀번호 입력, 마스킹 표시 |
| 로그인 | Form Submit Button (Primary) | 관리자 인증 요청 후 사용자 관리 페이지로 이동 |
| 로그인 안내 | Sidebar Text | 미로그인 상태에서 관리자 기능 이용 안내 |

### 기능 설명

- `POST /api/v1/admin/auth/login`으로 관리자 인증을 요청한다.
- 로그인 성공 시 응답의 `access_token`을 `st.session_state.access_token`에 저장한다.
- 입력한 아이디는 `st.session_state.user_id`에 저장한다.
- 아이디 또는 비밀번호가 비어 있으면 `모든 항목을 입력해 주세요.` 경고를 표시한다.
- API 오류는 `BackendAPIError` 메시지를 화면에 표시한다.
- 로그인 버튼 제출 후 `app_pages/user_management.py`로 이동한다.

### 현재 구현 유의사항

- 로그인 폼에 개발용 계정 정보가 기본값으로 입력되어 있다. 운영 배포 시 기본값 제거가 필요하다.
- 인증 실패 시에도 페이지 전환 코드가 실행될 수 있어, 성공 응답 확인 후 이동하도록 보완이 필요하다.
- Access Token만 저장하며 Refresh Token을 이용한 자동 갱신은 구현되어 있지 않다.

## 02. 사용자 관리 (User Management)

**파일:** `frontend_admin/app_pages/user_management.py`  
**스크린샷:** 미등록 (소스 기반 기술)  
**테마:** Streamlit 기본 Light 테마, rainbow divider

### 화면 구성

```text
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│ 대시보드 〉 사용자 관리                                                                 │
│ 사용자 관리                                                                             │
│─────────────────────────────────────────────────────────────────────────────────────────│
│ [사용자 검색 (이름, ID)       ] [전체 역할⌄] [전체 상태⌄] [＋ 사용자 추가]              │
│                                                                                         │
│ ┌─────────────────────────────────────────────────────────────────────────────────────┐ │
│ │ ID │ 사용자 아이디│ 역할 │ 경험치 │ 상태     │ 가입일 │ 마지막 접속일│ 관리         │ │
│ ├─────────────────────────────────────────────────────────────────────────────────────┤ │
│ │ …  │ id006        │ user │ 120    │ 활성화   │ …      │ …            │ [수정][삭제] │ │
│ │ …  │ user02       │ user │  40    │ 비활성화 │ …      │              │ [수정][삭제] │ │
│ └─────────────────────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 주요 UI 요소

| 요소 | 유형 | 설명 |
|---|---|---|
| 대시보드 〉 사용자 관리 | Breadcrumb | 현재 메뉴 위치 표시 |
| 사용자 검색 | Text Input | 이름 또는 ID 검색을 의도한 입력창 |
| 전체 역할 | Selectbox | 전체 역할, 일반, 관리자 선택 |
| 전체 상태 | Selectbox | 전체 상태, 활성, 비활성 선택 |
| ＋ 사용자 추가 | Primary Button | 사용자 추가 기능을 위한 버튼 |
| 사용자 목록 | Border Container + Columns | 사용자 계정 정보를 행 단위로 표시 |
| 수정 | Button | 선택한 로그인 아이디를 세션에 저장하고 상세보기로 이동 |
| 삭제 | Button | 선택한 사용자 UUID를 세션에 저장 |

### 목록 표시 필드

| 화면 컬럼 | API 필드 | 표시 규칙 |
|---|---|---|
| ID | `id` | 사용자 UUID |
| 사용자 아이디 | `login_id` | 로그인 아이디 |
| 역할 | `role` | 현재는 `user` 역할만 행으로 표시 |
| 경험치 | `user_exp` | 누적 사용자 경험치 |
| 상태 | `is_active` | `활성화` 또는 `비활성화` |
| 가입일 | `created_at` | API 응답 문자열 그대로 표시 |
| 마지막 접속일 | `last_login_at` | 값이 없으면 빈 문자열 |
| 관리 | - | 수정·삭제 버튼 |

### 기능 설명

- `GET /api/v1/admin/users`로 사용자 목록을 조회한다.
- 수정 버튼 클릭 시 `selected_item_login_id`에 로그인 아이디를 저장한다.
- 저장된 로그인 아이디를 기준으로 사용자 관리 상세보기 화면을 연다.
- 관리자 역할 항목은 응답에 포함되더라도 현재 목록 행에서 제외한다.

### 현재 구현 유의사항

- 검색어, 역할, 상태 입력값이 API Query Parameter에 연결되어 있지 않다.
- 페이지네이션 정보(`page`, `size`, `total`, `total_pages`)를 표시하거나 조작하지 않는다.
- 사용자 추가 버튼은 동작이 연결되어 있지 않다.
- 삭제 버튼은 사용자 ID만 세션에 저장하며 확인창과 삭제 API 호출은 없다.
- 목록 API 오류를 이 페이지 내부에서 별도로 처리하지 않는다.

## 03. 사용자 관리 상세보기 (User Detail)

**파일:** `frontend_admin/app_pages/user_management_detail.py`  
**하위 컴포넌트:** `frontend_admin/tab_pages/data/profile_tab.py`, `quest_tab.py`  
**스크린샷:** 미등록 (소스 기반 기술)  
**테마:** Streamlit 기본 Light 테마

### 화면 구성

```text
┌──────────────────────────────────────────────────────────────┐
│ [←뒤로 가기]                                                 │
│                                                              │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ [캐릭터]   id006               사용자                    │ │
│ │            사용자              2026-08-01T...            │ │
│ │                                활성                      │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ [프로필] [퀘스트 진행] [접속기록]                            │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 선택한 탭의 콘텐츠                                       │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### 상단 계정 요약

| 요소 | API 필드 | 설명 |
|---|---|---|
| 캐릭터 이미지 | `resources/캐릭터.png` | 70px 너비의 기본 사용자 이미지 |
| 사용자 아이디 | `account.login_id` | 큰 제목으로 표시 |
| 역할 | `account.role` | `user`는 `사용자`로 변환 |
| 가입일 | `account.created_at` | 계정 생성 시각 |
| 상태 | `account.is_active` | `활성` 또는 `비활성` |

### 탭 구성

| 탭 | 데이터 | 현재 표시 방식 |
|---|---|---|
| 프로필 | `account.profile` | 프로필이 있으면 `target_role`만 표시, 없으면 안내 문구 |
| 퀘스트 진행 | `quests` | 전체 퀘스트 배열을 DataFrame으로 표시 |
| 접속기록 | `last_login_at` 예정 | 현재 `last login info` 고정 문구만 표시 |

### 기능 설명

- 사용자 목록에서 선택한 `selected_item_login_id`를 사용한다.
- `GET /api/v1/admin/users/by-login-id/{login_id}/overview`로 계정·프로필·계획·퀘스트·로드맵 이력을 한 번에 조회한다.
- 뒤로 가기 버튼은 사용자 관리 목록으로 이동한다.
- API 오류는 문자열로 화면에 표시한다.

### 현재 구현 유의사항

- 상세 URL을 직접 열어 `selected_item_login_id`가 없으면 화면 실행 오류가 발생할 수 있다.
- Overview 응답 중 `plans`, `quest_progress`, `roadmap_history`, `last_login_at`은 아직 화면에 활용하지 않는다.
- 사용자 정보 편집, 활성·비활성 전환, 삭제 기능은 상세 화면에 구현되어 있지 않다.
- 프로필 상세 필드와 퀘스트 표 컬럼에 대한 사용자 친화적 라벨 변환이 필요하다.

**파일:** `frontend_admin/app_pages/loadmap.py`  
**스크린샷:** 미등록 (소스 기반 기술)  
**테마:** Streamlit 기본 Light 테마, rainbow divider

### 화면 구성

```text
┌──────────────────────────────────────────────────────────────┐
│ 대시보드 〉 로드맵 관리                                      │
│ 로드맵 관리                                                  │
│──────────────────────────────────────────────────────────────│
│ 회원가입 시 사용한 로그인 아이디로 로드맵 이력을 조회합니다. │
│                                                              │
│ 대상 사용자 로그인 아이디                                    │
│ [예: roadmap_user                             ] [로드맵 조회]│
│                                                              │
│ ✓ id006 사용자의 로드맵 2건을 조회했습니다.                  │
│                                                              │
│ ▼ 백엔드 개발자 취업 로드맵 · active                         │
│ ┌──────────────┬──────────────┬──────────────┐               │
│ │ 기간         │ 퀘스트       │ 진행률       │               │
│ │ 08-01 ~ 09-30│ 12           │ 42%          │               │
│ └──────────────┴──────────────┴──────────────┘               │
│ ████████░░░░░░░░░░░ 42%                                      │
│ 로드맵 요약                                                  │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 제목 │ 종류 │ 상태 │ 예정일                              │ │
│ └──────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### 주요 UI 요소

| 요소 | 유형 | 설명 |
|---|---|---|
| 대상 사용자 로그인 아이디 | Text Input | 조회할 일반 사용자 로그인 아이디 입력 |
| 로드맵 조회 | Form Submit Button (Primary) | 사용자별 로드맵 이력 API 호출 |
| 조회 결과 안내 | Success Message | 사용자 아이디와 로드맵 건수 표시 |
| 로드맵 제목·상태 | Expander | 로드맵별 접기·펼치기, 첫 항목은 기본 펼침 |
| 기간 | Metric | `starts_on ~ ends_on` |
| 퀘스트 | Metric | 해당 로드맵의 퀘스트 수 |
| 진행률 | Metric + Progress | 0~100 범위로 보정한 진행률 |
| 퀘스트 목록 | DataFrame | 제목, 종류, 상태, 예정일 표시 |

### 입력 및 상태 처리

- 사용자 관리에서 선택했던 `selected_item_login_id`가 있으면 검색창 기본값으로 사용한다.
- 입력값 앞뒤 공백을 제거한 뒤 조회한다.
- 빈 아이디 제출 시 경고를 표시하고 이전 조회 결과를 제거한다.
- 정상 응답은 `admin_roadmap_lookup_result` 세션 상태에 저장해 Streamlit 재실행 후에도 유지한다.
- 응답에 `login_id` 또는 `items`가 없으면 형식 오류로 처리한다.
- 로드맵이 없으면 `생성된 로드맵 이력이 없습니다.`를 표시한다.
- 퀘스트가 없으면 해당 Expander 안에 안내 문구를 표시한다.

### 기능 설명

- `GET /api/v1/admin/users/by-login-id/{login_id}/roadmaps`를 호출한다.
- 여러 로드맵 이력을 각각 독립된 Expander로 표시한다.
- 로드맵별 기간, 퀘스트 수, 진행률, 요약과 퀘스트 상세를 확인할 수 있다.
- API 연결·검증 오류는 Error Message로 표시하며 이전 결과를 제거한다.

## 시스템 공통 사항

### 인증 체계

| 항목 | 구현 방식 |
|---|---|
| 인증 API | `POST /api/v1/admin/auth/login` |
| 인증 토큰 | Bearer Access Token |
| 토큰 저장소 | `st.session_state.access_token` |

| 로그인 판별 | Access Token 문자열 존재 여부 |
| 로그아웃 | Access Token과 사용자 아이디를 빈 문자열로 초기화 |
| 로그아웃 후 이동 | 관리자 로그인 화면 |

### 백엔드 연결

| 대상 | 환경변수 | 기본 URL | 용도 |
|---|---|---|---|
| 사용자 Backend | `BACKEND_USER_URL` | `https://aio-01-p1-team2-1.onrender.com/api/v1` | 사용자 서비스 API 호출용 |
| 관리자 Backend | `BACKEND_ADMIN_URL` | `https://aio-01-p1-team2.onrender.com/api/v1` | 관리자 인증·운영 API 호출용 |

- 인증이 필요한 요청에는 `Authorization: Bearer {access_token}` 헤더를 자동 추가한다.
- 공통 요청 제한 시간은 60초다.
- 알 수 없는 Backend 역할은 사용자 Backend로 우회하지 않고 오류로 처리한다.

| 상황 | 화면 메시지 또는 처리 |

### 운영 전 우선 확인 사항

1. 로그인 폼의 개발용 기본 계정 정보를 제거한다.
2. 각 관리자 페이지에 인증 가드를 적용하고 앱 시작 시 `/admin/auth/me`로 토큰을 검증한다.
3. 동작이 연결되지 않은 버튼은 API를 연결하거나 비활성·준비 중 상태로 표시한다.
4. 삭제 동작에는 대상 정보, 확인 단계, 성공·실패 피드백을 추가한다.
5. 목록 화면에 API 기반 검색·필터·페이지네이션을 연결한다.
6. 직접 URL 접근 시 필요한 세션 키가 없는 경우 목록 화면으로 안전하게 이동한다.
7. 채용공고 페이지를 실제 제공할 경우 네비게이션 등록과 Backend 쓰기 API 범위를 먼저 확정한다.
