# AI_JOB_COACH 화면 설계 — 현재 구현 기준 수정본

> 현재 Streamlit 소스에 실제로 존재하는 화면만 기록한다. 목표 화면은 별도 미구현 목록으로 구분한다.

## 현재 화면 구조

`frontend_user`와 `frontend_admin`은 거의 동일한 교육용 Multi Tab 샘플 구조를 사용한다.

```text
app.py
app_pages/
├── start.py
├── example.py
└── chat_example.py
tab_pages/
├── start/
│   ├── home_tab.py
│   └── signup_tab.py
└── data/
    ├── chart_tab.py
    ├── dataframe_example_tab.py
    ├── item_search_example_tab.py
    └── log_tab.py
```

## 사용자 프런트엔드

| 화면 | 현재 구현 | 비고 |
|---|---|---|
| 시작 | 샘플 홈·회원가입 탭 | 실제 사용자 인증 API와 통합되지 않음 |
| 로그인 | `id01 / pwd01` 고정 샘플 | JWT 인증 아님 |
| 데이터 예제 | 차트·DataFrame·Item 조회 샘플 | 취업 서비스 도메인 화면 아님 |
| 채팅 예제 | Gemini 호출 UI 샘플 | 완성된 AI 코치 세션 UI 아님 |

## 관리자 프런트엔드

| 화면 | 현재 구현 | 비고 |
|---|---|---|
| 시작 | 사용자 샘플과 유사한 탭 | 관리자 전용 UX 아님 |
| 로그인 | 고정 샘플 인증 | 관리자 백엔드 로그인 API 없음 |
| 데이터 예제 | 차트·표·로그·Item 검색 샘플 | 실제 사용자·공지 관리 화면 아님 |
| 채팅 예제 | 샘플 채팅 | 관리자 핵심 기능과 무관 |

일부 관리자 프런트 파일은 `frontend_user` 모듈을 import하므로 두 프로젝트가 독립 실행 구조로 완전히 분리되어 있지 않다.

## 현재 제공되는 공통 상태

- 입력 폼
- 성공·오류 메시지
- 간단한 로그인 Session State
- 표·차트 샘플

로딩, 인증 만료, 권한 없음, 빈 상태, 삭제 확인 등 제품 수준의 공통 상태는 일관되게 구현되어 있지 않다.

## 미구현 목표 화면

### 사용자

- 실제 로그인·회원가입
- AI 온보딩 진단
- 취업 프로필·역량 평가
- 맞춤 로드맵
- 오늘의 퀘스트와 EXP
- 공고 추천·저장·상세
- 공고 기반 계획 변경 승인
- 취업 상담·서류·면접 지원

### 관리자

- 관리자 로그인
- KPI 대시보드
- 사용자 목록·상세·상태 관리
- 공지사항 CRUD 화면
- 취업 공고 관리
- 로드맵·퀘스트 관리
- AI 로그·피드백 모니터링

## 다음 구현 시 화면 원칙

- 사용자와 관리자 앱을 독립적으로 실행한다.
- 프런트엔드는 Supabase에 직접 접근하지 않고 FastAPI만 호출한다.
- JWT는 URL이 아닌 요청 Header에 전달한다.
- 목록 화면에는 검색·필터·페이지네이션·빈 상태를 제공한다.
- 삭제·비활성화 같은 작업은 확인 단계를 둔다.
- 화면 설계는 실제 API가 확정된 뒤 API 계약과 함께 갱신한다.
