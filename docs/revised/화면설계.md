# AI 취업 코치 화면 설계서 — 최종 문서

## 1. 전체 화면 구조

```text
사용자 앱
├─ 회원가입 / 로그인
├─ 홈 / 대시보드
├─ AI 온보딩
├─ 프로필 / 계정 설정
├─ 로드맵
├─ 오늘의 퀘스트
├─ 취업 공고
└─ AI 취업 상담

관리자 앱
├─ 관리자 로그인
├─ 운영 대시보드
├─ 사용자 관리
│  └─ 사용자 상세: 프로필 / 퀘스트 진행 / 접속 기록
├─ 로드맵 관리
├─ 공지사항
│  └─ 공지 상세
└─ 채용공고 관리
   └─ 채용공고 상세(조회 전용)
```

## 2. 관리자 공통 내비게이션

- 미로그인 상태에는 로그인 안내만 표시한다.
- 로그인 후 사이드바에 대시보드, 사용자 관리, 로드맵 관리, 공지사항, 채용공고 관리와 로그아웃 버튼을 표시한다.
- Access Token은 Streamlit `session_state`에 저장한다.
- API 클라이언트는 인증 요청에 Bearer Token을 자동으로 붙인다.
- 로그아웃은 `access_token`, `user_id`를 비우고 로그인 화면으로 이동한다.

## 3. 관리자 화면별 설계와 구현 상태

| 화면          | 주요 구성                                                                 | 호출 API                        | 상태                                             |
| ------------- | ------------------------------------------------------------------------- | ------------------------------- | ------------------------------------------------ |
| 관리자 로그인 | 아이디, 비밀번호, 로그인 버튼                                             | `POST /admin/auth/login`        | 연결 완료                                        |
| 대시보드      | 기간 입력, 사용자 KPI, 온보딩·평가, 가입 추이, 로드맵·퀘스트, 최근 가입자 | `GET /admin/dashboard`          | 연결 완료                                        |
| 사용자 목록   | 검색어, 역할, 활성 상태, 계정 표, 상세 버튼                               | `GET /admin/users`              | 목록 연결, 화면 필터는 서버 Query 연동 보완 필요 |
| 사용자 상세   | 계정·EXP, 프로필 탭, 퀘스트 탭, 접속 기록 탭                              | 상세·overview API               | 연결 완료                                        |
| 로드맵 관리   | 로그인 아이디 입력, 계획별 퀘스트와 진행률                                | `GET /admin/users/.../roadmaps` | 조회 연결 완료                                   |
| 공지 목록     | 공지 목록, 상세·삭제 버튼, 추가 버튼                                      | `GET /admin/notices`            | 목록·상세 연결, 생성·수정·삭제 미연결            |
| 공지 상세     | 선택한 공지 내용, 뒤로 가기                                               | `GET /admin/notices/{id}`       | 조회 연결 완료                                   |
| 채용공고 목록 | 저장 공고 표, 상세 버튼                                                   | `GET /admin/saved-jobs`         | 조회 연결 완료                                   |
| 채용공고 상세 | 회사·직무·마감일·본문·추출 데이터                                         | 목록에서 전달한 데이터          | 조회 전용, 저장 API 없음                         |

### 3.1 관리자 로그인 화면

```text
┌──────────────────────────────┐
│ 관리자 로그인               │
│ 아이디      [____________]   │
│ 비밀번호    [____________]   │
│              [ 로그인 ]      │
└──────────────────────────────┘
```

- 성공: Token 저장 후 대시보드로 이동
- 입력 누락: 경고 메시지
- 인증·서버 실패: API 오류 메시지 표시
- 현재 소스에 개발용 기본 아이디·비밀번호 값이 들어 있으므로 운영 배포 전 제거해야 한다.

### 3.2 대시보드

```text
조회 기간 [1..90일]
┌ 전체 사용자 ┬ 활성 계정 ┬ 신규 가입 ┬ 퀘스트 완료율 ┐
├ 온보딩 완료율 / 평가 현황 / 가입자 추이 차트          ┤
├ 활성 로드맵 / 전체 퀘스트 / 오늘 일정                ┤
└ 최근 가입 사용자 표                                  ┘
```

- 기간 변경 시 대시보드 API를 다시 호출한다.
- 가입 추이 또는 최근 사용자가 없으면 빈 데이터 안내를 표시한다.
- API 실패 시 화면 상단에 오류 메시지를 표시한다.

### 3.3 사용자 관리

- 목록 열: 로그인 아이디, 역할, 활성 상태, 누적 EXP, 최근 접속 등
- 상세 화면 탭:
  - 프로필: 목표 직무, 기술, 경험, 근무 환경, 역량 평가
  - 퀘스트 진행: 전체 퀘스트, 계획 진행률
  - 접속 기록: 최근 로그인 시각
- 백엔드에는 활성 상태 변경과 영구 삭제 API가 있으나 현재 화면 버튼은 완전히 연결되지 않았다.

### 3.4 로드맵 관리

- 관리자 입력: 사용자 `login_id`
- 출력: 계획 제목·상태·기간, 계획별 퀘스트, 완료·진행·대기 수와 진행률
- 잘못된 아이디 또는 저장소 오류는 경고·오류 메시지로 표시한다.
- 현재 기능은 조회 중심이며 로드맵 직접 편집 기능은 없다.

### 3.5 공지 및 채용공고

- 공지 CRUD API는 백엔드에 존재하지만 프론트엔드는 목록·상세 조회만 실제 연결되어 있다.
- 공지의 추가·수정·삭제 버튼은 화면 구조 또는 주석 수준이므로 완료 기능으로 보지 않는다.
- 채용공고 관리자 API는 읽기 전용이며 상세 화면 입력 컴포넌트도 비활성화되어 있다.

## 4. 사용자 화면

현재 사용자 프론트엔드는 로그인·회원가입, 홈·대시보드, 온보딩, 프로필, 계정 설정, 로드맵, 오늘의 퀘스트, 채용 공고, AI 상담 페이지와 각 도메인 API 클라이언트를 포함한다.

| 화면             | 목적                                   |
| ---------------- | -------------------------------------- |
| 회원가입·로그인  | 자체 계정 인증 및 사용자 세션 생성     |
| 온보딩           | Gemini 대화를 통해 목표·역량 정보 수집 |
| 대시보드         | 사용자 현황과 주요 이동 경로 제공      |
| 프로필·계정 설정 | 목표·역량·계정 정보 확인 및 변경       |
| 로드맵           | 제안·활성 계획과 일정 확인             |
| 오늘의 퀘스트    | 오늘 일정과 완료 상태 관리             |
| 취업 공고        | 저장·추천 공고 확인                    |
| AI 상담          | 취업 상담 세션 진행                    |

권장 화면 배치:

```text
┌ 사용자 대시보드 ─────────────────────────────┐
```

| ---------------- | ------------------------------------- | ------------------------ |

| 퀘스트 완료      | 성공 메시지와 캐릭터 강조 효과        | 퀘스트 상태·진행률       |
| 일일 목표 달성   | EXP 증가와 성장 가능 안내             | 일일 목표 달성 기록      |
| 레벨 변경        | 다음 단계 캐릭터와 축하 피드백        | 추후 확정할 레벨 정책    |
| 데이터 없음·오류 | 기본 캐릭터와 재시도 안내             | API 응답 상태            |

접근성 원칙:

- 이미지마다 단계와 행동을 설명하는 대체 텍스트를 제공한다.
- 레벨을 색상이나 캐릭터 외형만으로 전달하지 않고 단계명과 EXP를 함께 표시한다.
- 애니메이션을 적용할 경우 사용자 설정에 따라 정지할 수 있도록 한다.
- 모바일·좁은 화면에서는 4개 이미지를 한 열 또는 가로 스크롤로 재배치한다.

## 5. 상태·피드백 규칙

| 상태      | 표현 원칙                           | 현재 적용                                  |
| --------- | ----------------------------------- | ------------------------------------------ |
| 로딩      | API 호출 중 사용자 입력 중복 방지   | Streamlit 실행 상태 중심, 화면별 통일 필요 |
| 성공      | 성공 메시지 또는 갱신된 데이터 표시 | 일부 화면 적용                             |
| 빈 데이터 | 빈 표 대신 안내 메시지              | 대시보드·로드맵 등 적용                    |
| 입력 오류 | 해당 입력 근처 경고                 | 로그인·로드맵 적용                         |
| 인증 오류 | 로그인 재요청·세션 정리             | 기본 접근 제어 적용, 자동 전환 보완 필요   |
| 서버 오류 | `BackendAPIError` 메시지 표시       | 주요 연결 화면 적용                        |
| 삭제 확인 | 확인 후 실행                        | 미완성                                     |

## 6. 남은 화면 작업

1. 공지 등록·수정·삭제 폼과 확인 모달을 관리자 CRUD API에 연결한다.
2. 사용자 활성 상태 수정·영구 삭제 버튼을 연결한다.
3. 사용자 목록 검색·역할·상태·페이지 입력을 서버 Query에 연결한다.
4. AI 로그·KPI·피드백 관리자 화면을 추가한다.
5. 저장 공고가 읽기 전용임을 UI에서 명확히 유지하거나 변경 API를 별도로 설계한다.
6. 만료·무효 Token 응답 시 로그인 화면으로 자동 전환한다.
7. 버튼, 폼, 표, 차트, 로딩·빈 데이터·오류 상태의 디자인 규칙을 통일한다.

## 7. 정보 계층 구조

```text
서비스
├─ 사용자 영역
│  ├─ 인증
│  ├─ 현재 상태: 대시보드·프로필
│  ├─ 실행: 로드맵·오늘의 퀘스트
│  ├─ 탐색: 채용 공고
│  └─ 지원: AI 상담·공지·계정 설정
└─ 관리자 영역
   ├─ 인증
   ├─ 운영 현황: KPI 대시보드
   ├─ 사용자 운영: 목록·상세·로드맵
   ├─ 콘텐츠 운영: 공지·채용공고
   └─ AI 운영: 로그·KPI·피드백(화면 미구현)
```

## 8. 필수 화면 와이어프레임

### 8.1 메인 화면 — 운영 대시보드

```text
┌ 사이드바 ─────┬──────────────────────────────────────┐
│ 대시보드      │ 대시보드              기간 [7일 ▼] │
│ 사용자 관리   ├────────┬────────┬────────┬──────────┤
│ 로드맵 관리   │사용자수│활성계정│신규가입│퀘스트율  │
│ 공지사항      ├────────┴────────┴────────┴──────────┤
│ 채용공고      │ 온보딩/평가       가입자 추이 차트 │
│ 로그아웃      ├─────────────────────────────────────┤
│               │ 로드맵·퀘스트 KPI / 최근 사용자 표 │
└───────────────┴─────────────────────────────────────┘
```

### 8.2 상세 화면 — 사용자 상세

```text
┌ [← 목록]  roadmap_user  활성  EXP 40 ┐
├ [프로필] [퀘스트 진행] [접속 기록]    ┤
│ 목표 직무 / 기술 / 경험 / 역량 평가   │
│ 또는 퀘스트 표와 진행률                │
└────────────────────────────────────────┘
```

### 8.3 입력 화면 — 공지 등록·수정 목표안

```text
┌ 공지 등록/수정 ───────────────────────┐
│ 제목 [_____________________________]  │
│ 내용 [                              ] │
│      [                              ] │
│ [취소]                     [저장]     │
└────────────────────────────────────────┘
```

현재 백엔드 CRUD는 있으나 이 입력 화면은 아직 API와 연결되지 않았다.

### 8.4 설정 화면 — 관리자 세션·조회 설정 목표안

```text
┌ 관리자 설정 ──────────────────────────┐
│ 현재 계정: admin001                    │
│ 기본 조회 기간 [7일 ▼]                │
│ 로그 자동 새로고침 [끔/켬] 주기 [10초]│
│                         [설정 저장]    │
└────────────────────────────────────────┘
```

현재 별도 설정 페이지와 자동 로그 새로고침은 구현되지 않았다.

### 8.5 오류 화면

```text
┌ 데이터를 불러오지 못했습니다 ────────┐
│ 서버 또는 네트워크 상태를 확인하세요. │
│ 오류 코드: STORAGE_UNAVAILABLE         │
│ [로그인으로]                 [재시도]  │
└────────────────────────────────────────┘
```

현재는 주로 `st.error()`를 사용하며 오류 코드·재시도 버튼은 화면별 추가가 필요하다.

| 화면 여백 | 좌우 24px, 카드·열 간 16px 목표                |
| 표        | 헤더 고정, 행 단위 상세 이동, 빈 데이터 메시지 |
| 차트      | 동일 기간 필터 공유, 축·단위·범례 표시         |
| 버튼 상태 | Default·Hover·Disabled·Loading·Success·Error   |

Streamlit 기본 테마를 사용하고 있어 색상과 간격이 모든 화면에서 강제되지는 않는다. 위 표는 통일을 위한 목표 규칙이다.

## 11. 로그 대시보드 목표 화면과 현재 차이

가이드의 핵심 화면은 요청량·오류율·평균 응답시간, 시간대별 로그 추이, 레벨·기간 필터, 로그 상세와 피드백을 한 화면에서 연결해야 한다. 현재 관리자 프론트는 사용자·로드맵·퀘스트 운영 대시보드만 제공하며 AI 로그 시각화 페이지는 없다. 따라서 화면 설계 요구는 문서에 포함됐지만 구현 완료 상태는 아니다.
