## 2. 최우선 보완 작업

### P0 — 보안·실행 안정성

1. 관리자 로그인 화면에 하드코딩된 개발용 아이디·비밀번호 기본값을 제거한다.
2. 배포 환경에서 사용자·관리자 JWT 발급·검증 설정이 일치하는지 확인한다.
3. `app.ai_logs`, `app.admin_log_summary`, `app.feedback`의 실제 DB 존재 여부를 확인하고 migration을 저장소에 추가한다.
4. 원격 Supabase에 00~12 및 공지 SQL이 순서대로 적용됐는지 검증한다.
5. 만료·무효 Token 응답 시 관리자 프론트를 로그인 화면으로 자동 전환한다.

### P1 — 관리자 화면 완성

1. 사용자 목록의 검색·역할·상태·페이지 UI를 서버 Query와 연결한다.
2. 사용자 활성 상태 변경과 영구 삭제를 확인 절차와 함께 연결한다.
3. 공지 등록·수정·삭제 화면을 기존 CRUD API에 연결한다.
4. AI 로그 목록·상세·KPI와 피드백 모니터링 화면을 추가한다.
5. 로드맵 화면에 계획 상태·기간·진행률 필터와 빈 데이터 상태를 보완한다.

### P2 — 문서·DB 일관성

1. `backend_admin/README.md`의 초기 예제 설명을 현재 관리자 서비스 설명으로 교체한다.
2. 공지 SQL의 관리자·사용자 버전 차이를 정리해 단일 migration 흐름으로 만든다.
3. 사용자 SQL 00~22의 적용 순서, 재실행 가능 여부와 rollback 절차를 문서화한다.
4. OpenAPI와 수동 API 명세의 경로·모델을 CI에서 비교한다.
5. 논리·물리 ERD와 실제 Supabase 스키마를 다시 추출해 일치 여부를 검증한다.

### P3 — 테스트·배포 검증

1. 관리자 로그인 → 대시보드 → 사용자 상세 → 로드맵 → 공지 → 공고 E2E를 작성한다.
2. 인증 없음·권한 없음·Token 만료·빈 데이터·DB 오류 시나리오를 추가한다.
3. 공지 CRUD와 사용자 상태 변경·삭제 API 테스트를 보강한다.
4. 프론트엔드 클라이언트 테스트와 페이지 smoke test를 실행한다.
5. Render 배포 URL의 `/docs`, `/openapi.json`과 핵심 API를 실제 호출해 검증한다.
